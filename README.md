# modern_stock_api

The Spring Boot REST API for **ModernStock**, the stock management system in [PLAIN.md](../doc/plain/PLAIN.md).
It covers accounts, businesses, branches and warehouses, members and roles, products, stock, purchases and the POS. Swagger documents every endpoint.

| | |
|---|---|
| Stack | Java 17+, Spring Boot 3.5, Spring Security (JWT), Spring Data JPA, Flyway, PostgreSQL, springdoc (Swagger UI) |
| Base URL | `http://localhost:8080/api/v1` |
| Swagger UI | <http://localhost:8080/api/v1/swagger-ui.html> |
| OpenAPI file | [docs/openapi.yaml](docs/openapi.yaml) (regenerated by `OpenApiExportTest`) |

## Run it

**Option 1: nothing to install (recommended for the team).** This starts the API with its own embedded PostgreSQL:

```bash
mvn spring-boot:test-run
```

- The database is kept in `.data/postgres` (port `54320`, user `postgres`, password `postgres`, so DBeaver can open it).
- To start fresh, delete that folder.

**Option 2: with your own PostgreSQL or Docker.** First create a database named `modern_stock`. Then:

```bash
# Windows PowerShell: $env:DB_PASSWORD="your-password"; mvn spring-boot:run
DB_URL=jdbc:postgresql://localhost:5432/modern_stock DB_USERNAME=postgres DB_PASSWORD=your-password mvn spring-boot:run
```

Flyway creates the tables on the first start. Without an active profile, the `dev` profile is used, which:

- seeds a demo business;
- returns verification, invitation and reset links in the API responses, so you can test without email.

## Try it in Swagger

1. `POST /auth/login` with `{"login": "owner@demo.com", "password": "Demo@1234"}` and copy `accessToken`.
2. Click **Authorize** and paste the token into **bearer**.
3. Call `GET /me/businesses`, then put the business `id` into **business** (`X-Business-Id`).
   - **branch** (`X-Branch-Id`) is optional: a branch ID, or `all`.
   - The POS and cash shifts need a branch. Give `branchId` in the request body, or set the **branch** header.
4. Try a sale with `POST /pos/checkout`:

```json
{ "items": [{ "productId": 4, "qty": 1 }],
  "payments": [{ "method": "CASH", "currency": "USD", "amount": 10 },
               { "method": "CASH", "currency": "KHR", "amount": 10000 }] }
```

Product 4 is the $12.35 rice. At a rate of 4,100, the total is ៛50,600, so the change is **៛400**, the same as the example in PLAIN.md 11.6.

Because of the dev profile's `persist-authorization`, Swagger remembers the three values when you reload the page.

## How a request works

```
Authorization: Bearer <JWT>   → who you are (the account only)
X-Business-Id: 1              → which business: checked against business_members on every request
X-Branch-Id: 2 | all          → which branch you are looking at (a member with one branch is always in it)
Accept-Language: km | en      → language of error messages
```

- **`BusinessContextFilter`** checks the membership, then adds the role's permissions as authorities. Controllers use `@PreAuthorize("hasAuthority('sale:create')")`.
- **Tenancy:**
  - Every tenant table has `business_id` and uses Hibernate `@TenantId`, so queries are filtered automatically.
  - `TenantRepository.get(id)` also checks the business, so an ID from another business returns 404.
- **Errors:** every error is an RFC 7807 `ProblemDetail` with a `code` (for example `INSUFFICIENT_STOCK`) and a translated `detail`.

### Single points of truth (PLAIN.md 8)

| Rule | Where |
|---|---|
| Only one class changes stock: ledger rows, levels, batches with the earliest expiry sold first, weighted average cost | `inventory/StockService` |
| Only one class decides what a plan allows | `billing/EntitlementService` |
| Document numbers `PREFIX-YYYYMM-0001`, safe under concurrency | `common/DocumentNumberService` |
| Customer and supplier balances | `money/BalanceService` |

## Tests

```bash
mvn test
```

The tests start the real API against a real PostgreSQL (embedded, no Docker needed) and call it over HTTP, the same way the web app does. They cover:

- sign-up and refresh-token rotation;
- tenant isolation;
- Khmer error messages;
- buying with average cost;
- the riel change example;
- rollback on insufficient stock;
- credit sales and payments;
- voids and cash shifts;
- transfers with a shortfall and with a return;
- cashier permissions;
- **two cashiers selling the last unit at the same moment** (one gets 201, the other 422).

`OpenApiExportTest` also writes [docs/openapi.yaml](docs/openapi.yaml).

## Configuration

| Variable | Default | Notes |
|---|---|---|
| `PORT` | `8080` | Change it when 8080 is taken, e.g. `PORT=8090 mvn spring-boot:test-run` |
| `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` | `jdbc:postgresql://localhost:5432/modern_stock`, `postgres`, `postgres` | |
| `JWT_SECRET` | dev-only value | At least 32 characters. Required with `prod` |
| `WEB_APP_URL` | `http://localhost:4201` | Used to build verification, invitation and reset links |
| `CORS_ORIGINS` | `http://localhost:4200,http://localhost:4201` | The website and the web app |
| `SPRING_PROFILES_ACTIVE` | `dev` | `prod` turns off demo data and dev links, and hides Swagger unless `SWAGGER_ENABLED=true` |

## Notes for the team

- **Java version:** PLAIN.md 9.1 says Java 21. The project builds with 17 (the JDK on this PC). Once everyone has JDK 21, raise `java.version` in `pom.xml`.
- **Mapping:** DTOs are Java records mapped by hand, instead of MapStruct. They are short, and Swagger reads them directly.
- **Testcontainers:** tests use embedded PostgreSQL rather than Testcontainers, because Docker Desktop is not always running. Both use a real PostgreSQL.
- **Emails:** they are written to the log for now (`MailService`). Use Spring Mail and Mailpit next.
